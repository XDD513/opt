# 系统设置：公开配置与管理端配置拆分

## 1. 背景与目标

- **问题**：原 `GET/PUT /api/system/settings` 对任意已登录用户返回/允许更新**完整**系统配置，包含邮件 SMTP 密码、安全策略等敏感项。
- **目标**：拆分「仅展示业务所需非密钥」与「管理端全量读写」，降低横向泄露面。

## 2. 接口约定（第一部分已实现）

| 方法 | 路径 | 鉴权 | 返回范围 |
|------|------|------|----------|
| GET | `/api/system/settings` | 管理员 `roleType == 1` | **全部分组**：`basic`、`notification`、`security`、`email` |
| GET | `/api/system/settings/public` | 任意已登录用户（`userId` 来自 JWT） | **公开分组**：仅 `basic`、`notification`（不含 `security`、`email`） |
| PUT | `/api/system/settings` | 管理员 `roleType == 1` | 写入数据库（行为与原先一致，仅增加权限校验） |

### 2.1 「公开」含义说明

- **不是**匿名可访问：仍须通过 Spring Security JWT，未登录返回 401。
- **排除项**：所有 `config_key` 映射到前端分组为 `security`、`email` 的条目不会出现在 `/settings/public` 中（例如 `email.password`、会话超时、登录锁定策略等）。

### 2.2 管理后台前端

- 管理员「系统设置」页继续使用 **`GET /api/system/settings`** 与 **`PUT /api/system/settings`**（管理员 Token 不变）。
- 若后续患者在业务页需要系统名称、预约规则等，应调用 **`GET /api/system/settings/public`**，勿拉全量接口。

## 3. 对 Nacos 的影响（重点）

### 3.1 结论：**HTTP 拆分不改变 Nacos 同步逻辑**

系统配置写入数据库后的同步链路仍为：

`SystemServiceImpl.updateSystemSettings` → 清理 Redis → `systemSettingManager.refresh()` → **`SystemSettingNacosSyncService.sync(systemSettingManager.snapshot())`**

- **触发条件**：仅在管理员调用 **`PUT /api/system/settings`** 且更新成功时触发（与拆分前相同）。
- **同步内容**：仍为当前库的**完整键值快照**（`Map<String,String>`），**不会**因为增加了 `/settings/public` 而只同步「公开子集」。Nacos 中的 `dataId`（如 `hospital-system-settings-<profile>.json`）仍承载**全量**业务配置，供依赖配置中心的组件使用。

### 3.2 为何无需改 Nacos dataId / Group

- Nacos 侧存储的是**服务端运行时真相**，需要包含邮件、安全等键，才能支撑发信、会话策略等功能。
- 本次变更解决的是 **REST 暴露面**：谁可以通过浏览器/脚本**读到**哪些键；不是缩小持久化或 Nacos 中的数据集。

### 3.3 配置项仍建议配合的环境

- `system.setting.sync.enabled`（或项目中等价开关）：关闭时**不会**向 Nacos `publishConfig`，与本次接口拆分无关。
- `bootstrap.yml` / `spring.cloud.nacos.config`：客户端拉取 Nacos **读取**行为不变。

### 3.4 运维检查清单（发布后）

1. 使用**患者账号**请求 `GET /api/system/settings` → 应 **403**。
2. 使用**患者账号**请求 `GET /api/system/settings/public` → **200**，响应中无 `security`、`email` 分组。
3. 管理员修改任意设置后，若启用同步，Nacos 控制台对应 dataId 版本仍更新（与原先一致）。

## 4. 后续可做事情（非本提交范围）

- 前端患者端页面若有需要，接入 `/settings/public`。
- `/api/config`（`FrontendConfigController`）与 Nacos 前端运行时配置的边界说明可单独文档化，避免与 `/settings/public` 重复拉数。
