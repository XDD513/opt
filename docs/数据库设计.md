# 中医体质辨识与健康管理系统 - 数据库设计文档

> **文档版本**: v1.1.0  
> **数据源**: 你在本轮消息中粘贴的 MySQL 建表脚本（Schema：`tcm_health_system`，含 `conversation` / `conversation_message` 等）

---

## 1. 设计原则
1. **三范式优先，关键场景适度反范式**：会话快照字段（如 `last_message_preview`、未读计数）保留在 `conversation`，避免频繁跨表统计。
2. **命名规范**：保持当前脚本的命名体系（`tcm_*`、`user_*`、`sys_*`、`conversation*`），字段采用 `snake_case`。
3. **时间字段统一**：`created_at` / `updated_at` 使用 `datetime`，`on update` 由数据库维护。
4. **软删除策略**：
   - 会话表使用 `deleted_by_*` 三路逻辑删除字段。
   - 会话消息表使用 `deleted`（当前业务主要用于过滤最近发送者）。
5. **JSON 字段规范**：扩展信息、列表字段采用 `json`/`text(JSON)`，并在文档中明确语义。

## 3. 核心表结构说明

### 3.1 会话表 `conversation`
- 主键：`id`（会话ID）
- 参与方：
  - `patient_id`（患者用户ID，快照字段）
  - `conversation_type`（如 `USER_USER` / `ADMIN_USER`）
  - `participant1_user_id` / `participant1_role`（通常患者：`PATIENT/ADMIN`）
  - `participant2_user_id` / `participant2_role`（对方：`PATIENT/ADMIN`）
- 会话快照：
  - `title` / `summary`
  - `patient_nickname` / `patient_avatar`
  - `last_message_preview`
  - `last_sender_role` / `last_sender_name` / `last_sender_avatar`
  - `last_message_time`
- 未读计数与状态：
  - `unread_for_patient` / `unread_for_participant1` / `unread_for_participant2`
  - `status`（`ACTIVE/ARCHIVED/DELETED`）
  - `deleted_by_patient` / `deleted_by_participant1` / `deleted_by_participant2`（0/1 逻辑删除）
- 时间字段：`created_at` / `updated_at`
- 关键索引（脚本中已定义）：`idx_conversation_patient`、`idx_conversation_status`、`idx_conversation_updated`、`idx_conversation_deleted_patient`、`idx_conversation_type`、参与方索引与删除索引。

### 3.2 会话消息表 `conversation_message`
- 主键：`id`（消息ID）
- 外键：`conversation_id`（引用 `conversation.id`，`ON DELETE CASCADE`）
- 发送方与内容：
  - `sender_role`（`PATIENT/ADMIN/SYSTEM`）
  - `sender_id`（发送者用户ID）
  - `sender_name` / `sender_avatar`
  - `content`（消息正文）
  - `content_type`（默认 `TEXT`；如 TEXT/IMAGE/FILE）
  - `attachment_url`（附件地址）
  - `metadata`（`json` 扩展信息）
- 已读/删除：
  - `is_read`（0-未读 / 1-已读）
  - `read_at`（阅读时间，预留）
  - `deleted`（0-否 / 1-是）
- 时间字段：
  - `sent_at`（发送时间，默认当前时间）
  - `created_at` / `updated_at`
- 关键索引（脚本中已定义）：
  - `idx_conversation_message_cid`、`idx_conversation_message_role`、`idx_conversation_message_time(sent_at desc)`

### 3.3 症状关键词 `symptom_keyword`
- `keyword`：`varchar(100)`（唯一索引 `uk_keyword`）
- `weight`：权重（默认 100）
- `usage_count`：使用次数（默认 0）
- `created_at` / `updated_at`
- 索引：`idx_weight`、`idx_usage`

### 3.4 同义词字典 `synonym_dictionary`
- `source_word` / `target_word`
- `synonym_type`（默认 `GENERAL`）
- `weight` / `usage_count` / `is_verified` / `created_by`
- `created_at` / `updated_at`
- 索引：`idx_source`、`idx_target`、`idx_type`、`idx_verified`

### 3.5 系统配置 `sys_config`
- `config_key`（唯一索引 `uk_config_key`）
- `config_value`（`text`）
- `config_desc` / `config_type`
- `created_at` / `updated_at`

### 3.6 数据字典 `sys_dictionary`
- 主键：`id`
- `dict_type`（字典类型）
- `dict_label`（标签）
- `dict_value`（值）
- `dict_sort` / `status` / `remark`
- 索引：`idx_dict_type`

### 3.7 操作日志 `sys_operation_log`
- `user_id` / `username`
- `operation_module` / `operation_type` / `operation_desc`
- `request_method` / `request_url` / `request_params`
- `response_data` / `ip_address` / `user_agent`
- `execution_time` / `status` / `error_msg`
- `created_at` / `updated_at`
- 索引：`idx_user_id`、`idx_operation_module`、`idx_operation_type`、`idx_status`、`idx_created_at`

### 3.8 用户表 `tcm_user`
- 主键：`id`
- 账号：`username`（唯一 `uk_username`）、`phone`（唯一 `uk_phone`）
- 身份与密码：`password`（BCrypt 加密存储）
- 基本信息：`real_name` / `email` / `gender` / `birthday` / `id_card` / `address` / `avatar`
- 角色与状态：`role_type`（0-患者 1-管理员）、`status`（0-禁用 1-启用）
- 登录统计：`last_login_time` / `login_count`
- `created_at` / `updated_at` / `version`
- 索引：`idx_role_type`、`idx_status`

### 3.9 用户体质测试 `user_constitution_test`
- 主键：`id`
- `user_id`
- `test_date`
- `primary_constitution` / `secondary_constitution`
- `test_result`（json）
- `report_generated`（0/1）
- `created_at` / `updated_at`
- 索引：`idx_user_id`、`idx_test_date`

### 3.10 用户收藏 `user_favorite`
- 主键：`id`
- `user_id`
- `target_type`（目标类型）
- `target_id`（目标ID）
- `remark`
- `created_at` / `updated_at`
- 唯一索引：`uk_user_target(user_id,target_type,target_id)`
- 索引：`idx_user_id`、`idx_target(target_type,target_id)`

### 3.11 用户养生档案 `user_health_profile`
- 主键：`id`
- `user_id`（唯一索引 `user_id`，一对一档案）
- 关键字段：`height/weight/bmi/blood_type/current_constitution/secondary_constitution` 等
- 大字段：`health_goals`、`allergies/medical_history/family_history/current_medications`（text(JSON)）
- 体检与报告：`last_checkup_date`、`checkup_report`
- `created_at` / `updated_at`
- 索引：`idx_user_id`、`idx_constitution(current_constitution)`

### 3.12 推荐设置 `user_recommendation_settings`
- 主键：`id`
- `user_id`（唯一）
- `weight_settings` / `other_settings`（均为 JSON text）
- `created_at` / `updated_at`

### 3.13 穴位与组合
- `tcm_acupoint`：穴位字段 + 索引（`idx_meridian`、`idx_category`）
- `tcm_acupoint_combination`：组合方案字段 + `idx_constitution`

### 3.14 药膳与食材
- `tcm_herbal_recipe`：食谱字段 + 索引（`idx_constitution`、`idx_season`、`idx_category`、`idx_status`、`idx_recipe_test_id`）
- `tcm_ingredient`：食材字段 + 索引（`idx_category`、`idx_status`）

### 3.15 健康打卡与方案执行
- `tcm_health_checkin`：每日打卡记录（`uk_user_date_type` 唯一约束）
- `tcm_health_plan_record`：方案执行记录（`idx_user_id`、`idx_status`、`idx_health_plan_test_id`）

### 3.16 会话/消息字段对齐要点
- 会话快照未读来源：`conversation.unread_for_*`
- 消息表的 `conversation_message.is_read/read_at` 字段当前作为结构预留（建议以会话未读计数为准）

## 4. ER 关系描述
1. **会话-消息关系**：`conversation (1) -> conversation_message (N)`
   - `conversation_message.conversation_id` 外键引用 `conversation.id`，`ON DELETE CASCADE`
2. **用户与健康相关表（建议外键）**：
   - `user_health_profile.user_id`、`user_constitution_test.user_id`、`tcm_health_checkin.user_id`、`tcm_health_plan_record.user_id` 等均应关联 `tcm_user.id`（当前脚本片段未显式声明外键，建议补充约束以便数据一致性）。
3. **收藏表多态**：
   - `user_favorite.target_type + target_id` 关联到不同业务表（不依赖单一外键）。

---

## 5. 索引与性能优化（基于当前建表索引）
1. **会话列表**：
   - 主要依赖：`conversation` 的 `idx_conversation_patient`、`idx_conversation_status`、`idx_conversation_updated` 等。
2. **会话消息列表**：
   - 主要依赖：`conversation_message` 的 `idx_conversation_message_cid` + `sent_at desc`。
3. **体质类型查询**：
   - `tcm_constitution_type.uk_type_code`（按 `type_code` 精确查询）。
4. **关键词/同义词召回**：
   - `symptom_keyword.uk_keyword`（唯一定位）
   - `symptom_keyword` 的 `weight/usage_count` 索引
   - `synonym_dictionary` 的 `source_word/target_word/synonym_type/is_verified` 索引
5. **打卡去重**：
   - `tcm_health_checkin.uk_user_date_type(user_id,checkin_date,checkin_type)`

## 6. 数据一致性与事务（与业务流程对齐）
1. **发送消息**：
   - 在事务内写入 `conversation_message`。
   - 更新 `conversation` 快照字段（`last_message_preview`、`last_sender_*`、`last_message_time`）与接收方未读计数（`unread_for_*`）。
2. **标记已读**：
   - 更新 `conversation.unread_for_*` 为 0。
   - `conversation_message.is_read/read_at` 当前实现中未必同步更新；若要强一致，可在后续完善中补齐。

---

## 7. 会话未读/已读规则（与表字段对齐）
1. **未读计数（会话快照）为主**：
   - `conversation.unread_for_patient`：患者侧未读
   - `conversation.unread_for_participant1`：参与者1侧未读
   - `conversation.unread_for_participant2`：参与者2侧未读
2. **消息表的已读字段为预留**：
   - `conversation_message.is_read` / `read_at` 字段用于结构支持，但当前接口更倾向以 `conversation.unread_for_*` 作为消息中心展示依据。
3. **已读更新接口**：
   - 通过 `PUT /api/conversations/{conversationId}/read` / `PUT /api/conversations/read-all` 将对应 unread 计数置零（具体置零逻辑由角色/入参决定）。

---

## 8. 数据安全与备份
1. **字符集与排序规则**：脚本使用 `utf8mb4` / `utf8mb4_unicode_ci`，支持中文与表情。
2. **密码存储**：`tcm_user.password` 使用 BCrypt 加密后再落库。
3. **审计与追踪**：`sys_operation_log` 记录关键增删改操作。
4. **备份策略**：建议每日全备 + 周期性增量备份，保留满足恢复目标的历史窗口。
