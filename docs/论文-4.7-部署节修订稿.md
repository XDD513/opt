## 4.7 多环境部署设计

系统采用多环境部署设计，划分为**开发环境**、**测试环境**、**生产环境**三个相互隔离的环境，各环境在**配置、数据、权限与变更流程**上区分，以保障开发、测试、上线的规范化。物理拓扑上，各环境均可采用**单台服务器 + Docker Compose** 拉起全套容器（与 `deploy/docker-compose.yml` 一致）；差异主要体现在**宿主机、环境变量、Nacos 命名空间、数据库实例与账号权限**等方面。

**(1) 开发环境**  
供开发人员日常开发与联调使用，资源规格可较低，便于快速迭代；连接**开发库**或本地/容器内 MySQL，数据为测试数据；开发人员权限较高，可频繁更新镜像与配置。通常在本机或内网测试机执行 Compose，并启用 `dev` 等 Spring Profile。

**(2) 测试环境**  
供测试与验收使用，容器组成宜与生产对齐，连接**独立测试库**，数据为脱敏或模拟数据；仅测试角色具备变更权限，代码与镜像发布应走测试流程，用于功能、接口与集成验证，降低带病上线风险。

**(3) 生产环境**  
供正式对外服务使用，宿主机应加固网络（安全组仅开放 80/443、按需开放运维端口），使用**生产库**存储真实用户数据；仅运维或经授权人员具备发布与主机权限，配置与镜像变更应经**测试通过及审批**。当前落地形态为**单机多容器**：在一台云服务器上通过 Docker Compose 编排全部服务；若业务量增长，可在**不否定现有架构叙述**的前提下，在论文「展望」中说明可演进为多节点与集群（数据库主从、Redis 高可用、多副本后端与负载均衡等）。

## 4.7.2 服务器部署方案（修订：单机 Docker 集中部署）

**（说明）** 本节以项目当前 `**deploy/docker-compose.yml`** 为准，描述**单台服务器**上通过 **Docker Compose** 统一部署前后端、数据库、缓存、消息队列、检索、配置中心与 AI 推理服务的方式；**不再采用**「前端 2 台、后端 4 台、MySQL 一主两从、Redis 三节点哨兵」等与当前实现不符的多机分配表述（上述可作为后续扩展方案在「系统展望」中简述）。

**(1) 前端与接入**  
由 `**frontend` 容器** 承载：内置 **Nginx**，托管构建后的 **Vue 静态资源**，并将 API 请求**反向代理**至同 Compose 网络内的 `**backend` 服务**（典型对外端口 **80:80**）。HTTPS 可在宿主机外层 SLB/证书网关终止，或由 Nginx 配置 SSL。

**(2) 后端应用**  
由 `**backend` 容器** 运行 **Spring Boot** 可执行包（如 `java -jar`，端口 **8000:8000**）。在 Compose 网络内访问 **MySQL、Redis、Nacos、RabbitMQ、Elasticsearch** 及 `**ai-service`** 等依赖；无状态设计配合 JWT 与 Redis 等，便于日后增加后端副本并在前置负载均衡下横向扩展。

**(3) 数据库**  
由 `**mysql` 容器** 提供 **MySQL 8.0**，数据卷持久化业务与 Nacos 元数据；生产环境应落实**定期备份**、**最小权限账号**与**强口令策略**。主从复制与读写分离可作为并发增长后的升级路径单独实施。

**(4) 缓存与中间件**  
`**redis`** 容器提供缓存等能力；`**rabbitmq**` 提供消息队列及管理控制台（**5672 / 15672**）；`**elasticsearch`** 以单节点模式运行（**9200**），支撑检索类能力；`**nacos`** 以 **standalone** 模式运行（**8848**），依赖 MySQL 存储配置与注册数据。各组件与业务容器**同机部署**，应配置容器资源上限与主机监控，避免相互挤占。

**(5) AI 推理服务**  
由 `**ai-service` 容器** 运行 **Python** 推理进程（如舌象检测，**5000**），后端经**内网 HTTP** 调用。若模型算力需求高，可将 AI 服务迁移至带 GPU 的独立主机，仅调整网络与 Compose 编排即可。

**(6) 部署图与文档索引**  
UML 部署图源文件：`docs/uml/figure-deployment-single-host-docker.puml`（导出为 PNG/SVG 可作为论文插图）。运维操作级说明见 `deploy/README-cloud.md`，总体架构说明见 `docs/系统架构设计.md` 第 8.2 节。
